Reinforcement learning, through the games our agents played

Reinforcement learning (RL) is learning to act from a score instead of from labeled answers. This lesson builds it up from the loop to the methods used to train language models, using the real episodes Claude Haiku and Qwen played on the Agent I/O page.

Supervised learning gets the right answer for every example. Reinforcement learning only gets a number after acting, often much later, like a backtest that reports profit and loss but never says which trades were "correct."

1The agent–environment loop

An agent sees an observation, picks an action, and gets back a reward and the next observation. Repeat until the episode ends.

One run from start to finish is an episode; its record is a trajectory:

$$\tau = (o_0,\ a_0,\ r_1,\ o_1,\ a_1,\ r_2,\ \dots,\ o_T)$$

In our code this is exactly the GEM (a gym library for language-model agents) interface: env.reset() returns \(o_0\), and env.step(action) returns the next observation, the reward, and whether the episode is over. The agent is the language model; its action is the text it writes, and only the last \boxed{...} counts as the move.

2Hidden state and beliefs

Theory usually assumes the agent sees the whole state. In our games it can't (the secret number is hidden), so the agent has to carry a summary of the past: a belief.

The standard model is a Markov decision process: states \(S\), actions \(A\), transition probabilities \(P\), rewards \(R\), and a discount \(\gamma\). "Markov" means the current state is all you need. The past adds nothing:

$$P(s_{t+1} \mid s_t, a_t) = P(s_{t+1} \mid s_0, a_0, \dots, s_t, a_t)$$

In Guess the Number the true state is the secret number, which the agent never sees. It only sees hints ("higher", "lower"). That makes it a partially observable Markov decision process: add observations \(o\) drawn from \(\Omega(o \mid s)\). The fix is to track a belief, a probability for every possible hidden state, updated with Bayes' rule after each observation:

$$b_{t+1}(s') \;\propto\; \Omega(o_{t+1} \mid s') \sum_{s} P(s' \mid s, a_t)\, b_t(s)$$

Here the secret never moves and hints are exact, so the belief is simply "uniform over the numbers still consistent with every hint." Uncertainty is measured in bits by the entropy:

$$H(b) = -\sum_s b(s)\log_2 b(s)$$

For a uniform belief over \(n\) numbers this is \(\log_2 n\).

At the start \(H = \log_2 20 \approx 4.32\) bits. A guess in the middle of the remaining range removes about 1 bit, so bisection always wins within \(\lfloor \log_2 20 \rfloor + 1 = 5\) guesses.

Guess the Number: watch the belief shrink

A belief is like a filtered estimate of a latent regime in a market model: you never observe the regime, only prices, so you carry a posterior forward and update it with each new bar.

3Rewards, returns and discounting

The agent maximizes the return: the sum of future rewards, usually discounted so that sooner rewards count more.
$$G_t = r_{t+1} + \gamma r_{t+2} + \gamma^2 r_{t+3} + \dots = \sum_{k=0}^{T-t-1} \gamma^k\, r_{t+k+1}$$ $$G_t = r_{t+1} + \gamma\, G_{t+1}$$

The discount \(\gamma \in [0,1]\) sets how far ahead the agent cares; a rough horizon is \(1/(1-\gamma)\) steps. The recursive form on the right is the seed of everything in the next section.

Rewards are a design choice. GEM's Wordle pays +0.5/3 ≈ +0.17 the first time each letter position turns green, +0.5 for solving, and −0.1 for a reply with no parseable guess (which also ends the game), so a perfect game totals 1.0. Partial credit along the way is called reward shaping. It speeds up learning, but it can change what the best strategy is unless it has a special "potential-difference" form (Ng, Harada and Russell, 1999). Here it pays partial credit even for a lost game, so it can reward finding letters over actually winning.

4Values and the Bellman equation

A value function predicts the return from a state. The Bellman equation says a state is worth its immediate reward plus the discounted worth of where you land. Apply that repeatedly and the values converge.

For a policy \(\pi\) (a rule for choosing actions), the state value and action value are expected returns:

$$V^\pi(s) = \mathbb{E}_\pi[\,G_t \mid s_t = s\,]$$ $$Q^\pi(s,a) = \mathbb{E}_\pi[\,G_t \mid s_t = s,\ a_t = a\,]$$

Plugging the recursive return \(G_t = r_{t+1} + \gamma G_{t+1}\) into the expectation gives the Bellman equation. For the best possible policy it becomes:

$$V^*(s) = \max_a \sum_{s'} P(s' \mid s, a)\,\big[\,R(s,a,s') + \gamma\, V^*(s')\,\big]$$

Value iteration turns that equation into an update and applies it to every state ("a sweep") until nothing changes. It always converges, because each sweep shrinks the worst-case error by a factor of \(\gamma\):

$$V_{k+1}(s) \leftarrow \max_a \sum_{s'} P(s' \mid s,a)\big[R + \gamma V_k(s')\big]$$ $$\lVert V_{k+1} - V^* \rVert_\infty \le \gamma\, \lVert V_k - V^* \rVert_\infty$$

This needs the rules (\(P\) and \(R\)), which a grid world gives us. The robot below starts bottom-left. The green cell pays +1 and ends the episode; the red cell pays −1 and ends it. Every other move costs a little, and with "slip" probability the robot moves sideways instead of where it meant to go.

Value iteration on a grid world

Try it: raise the slip and the arrows next to the red cell turn away from it, taking the long, safe route. Make moves expensive (−0.3) and the robot rushes, even risking the red cell. Lower γ and far-away cells stop "seeing" the goal.

This is a discounted cash-flow valuation: a position is worth its payoff now plus the discounted value of what it turns into. Value iteration is repeatedly re-pricing every position until the prices are consistent with each other.

5Exploration versus exploitation

An agent that always picks what currently looks best can lock onto a mediocre option and never discover a better one. Bandits isolate that trade-off.

A multi-armed bandit is a one-state problem: \(k\) slot machines, each paying 1 with an unknown probability \(\mu_a\). The cost of not knowing is regret, the reward lost compared with always pulling the best arm:

$$\text{Regret}_T = T\,\mu^* - \sum_{t=1}^{T} \mu_{a_t}$$

Three classic strategies, with \(\hat{Q}_a\) the observed average payout of arm \(a\) and \(N_a\) its pull count:

  • ε-greedy: pull the best-looking arm, except with probability ε pick at random. Simple, but it keeps exploring forever at the same rate, so regret grows linearly.
  • Upper confidence bound (UCB1): be optimistic about arms you know little about: \(a_t = \arg\max_a \big[\hat{Q}_a + \sqrt{2 \ln t / N_a}\big]\).
  • Thompson sampling: keep a Beta posterior per arm, \(\theta_a \sim \text{Beta}(1 + \text{wins}_a,\ 1 + \text{losses}_a)\), sample one plausible payout per arm, and pull the arm with the highest sample.

The best possible regret grows like \(\log T\) (Lai and Robbins, 1985); the upper confidence bound (UCB1) method and Thompson sampling both achieve that order.

Watch the shapes, not just the end values: ε-greedy's regret is a straight line (it never stops exploring), while the upper confidence bound (UCB1) method and Thompson sampling bend over like \(\log T\). Its confidence bonus is cautious, so it can trail early and win only over long runs; Thompson sampling is usually best in practice.

For language models, sampling with temperature is the exploration: the training methods in section 9 draw several different answers to the same question so that better ones get a chance to be found.

6Learning from experience: temporal-difference learning and Q-learning

Without knowing the rules, an agent can still learn values from its own moves: nudge each estimate toward "the reward I just got, plus how good I currently think the square I landed on is." The landing square is observed; only its value is a guess.

Value iteration needed \(P\) and \(R\). Real agents usually only get samples \((s, a, r, s')\). Two ways to learn from them:

  • Monte Carlo: wait until the episode ends, then move \(V(s_t)\) toward the actual return \(G_t\). Unbiased, but noisy and slow.
  • Temporal-difference learning: update after every step using your own estimate of the next state ("bootstrapping"). The gap is the temporal-difference error \(\delta\).

Q-learning applies temporal-difference learning to action values, using the best next action even when the agent explored:

$$\delta_t = r_{t+1} + \gamma \max_{a'} Q(s_{t+1}, a') - Q(s_t, a_t)$$ $$Q(s_t,a_t) \leftarrow Q(s_t,a_t) + \alpha\,\delta_t$$

Here \(\alpha\) is the learning rate. The robot below uses the same grid and settings as section 4, but it does not know the rules; it explores with ε-greedy and learns from its own steps.

Q-learning on the same grid world

Temporal-difference learning is how a rolling forecast gets updated: instead of waiting for the realized outcome, you correct today's forecast toward tomorrow's forecast plus what happened in between.

7Policy gradients

Instead of learning values, adjust the policy's probabilities directly: make actions that led to better-than-expected returns more likely. This is the family of methods used to train language models.

Give the policy parameters \(\theta\) and maximize the expected return \(J(\theta) = \mathbb{E}_{\tau \sim \pi_\theta}[G(\tau)]\). We can't differentiate through the environment, but the log-derivative trick \(\nabla_\theta p = p\,\nabla_\theta \log p\) moves the gradient onto the policy's own probabilities:

$$\nabla_\theta J(\theta) = \mathbb{E}_{\tau \sim \pi_\theta}\Big[\sum_t \nabla_\theta \log \pi_\theta(a_t \mid s_t)\;\big(G_t - b\big)\Big]$$

That is REINFORCE (Williams, 1992). Sample an episode, then push up the log-probability of each action in proportion to how good the outcome was. The baseline \(b\) can be any number that doesn't depend on the action, because \(\mathbb{E}[\nabla_\theta \log \pi_\theta] = 0\). It doesn't change the average gradient, but a good baseline (like the average return) shrinks its noise a lot. The quantity \(G_t - b\) is called the advantage: how much better than usual this outcome was.

For a softmax policy \(\pi(a) = e^{\theta_a} / \sum_b e^{\theta_b}\) the gradient is simple: \(\partial \log \pi(a) / \partial \theta_b = \mathbb{1}[a=b] - \pi(b)\).

REINFORCE with and without a baseline

Three actions pay noisy rewards averaging 1.0, 1.4 and 2.0, plus an offset added to every reward. The offset changes nothing about which action is best. With a baseline it changes nothing about learning either; without one, every sampled action gets pushed up, the bad ones included, and runs start locking onto the wrong action.

8From REINFORCE to proximal policy optimization (PPO)

PPO is REINFORCE with three upgrades: a learned critic supplies the baseline, advantages blend short and long lookahead, and a clipped objective lets each batch of samples be reused for several gradient steps without the policy running away from the data.

Step 1: a learned baseline (actor–critic)

REINFORCE's baseline \(b\) was one number for every state. A better baseline depends on the state: the value \(V(s_t)\) from section 4, learned by a second model called the critic (the policy is the actor). The advantage becomes "how much better was this action than what I expected from here":

$$A_t = Q(s_t, a_t) - V(s_t)$$

We don't know \(Q\) either, but one real step plus the critic's guess about the next state estimates it. That is the temporal-difference error from section 6, now applied to \(V\):

$$\delta_t = r_{t+1} + \gamma\, V_\phi(s_{t+1}) - V_\phi(s_t)$$

The critic \(V_\phi\) (parameters \(\phi\)) is trained by regression toward observed returns, \(L^V(\phi) = \big(V_\phi(s_t) - \hat{G}_t\big)^2\).

Step 2: how far to look ahead (generalized advantage estimation)

\(\delta_t\) uses one real reward and then trusts the critic. The full return \(G_t - V(s_t)\) trusts only real rewards. Generalized advantage estimation (GAE; Schulman et al., 2016) is a weighted blend of all the look-aheads in between, controlled by \(\lambda \in [0,1]\):

$$\hat{A}_t = \sum_{k=0}^{T-t-1} (\gamma\lambda)^k\, \delta_{t+k}$$
  • \(\lambda = 0\): \(\hat{A}_t = \delta_t\). Low noise, but wrong wherever the critic is wrong (biased).
  • \(\lambda = 1\): the sum telescopes to \(\hat{A}_t = G_t - V(s_t)\), the Monte Carlo advantage. Unbiased, but it carries the noise of every later step.

PPO usually uses \(\lambda \approx 0.95\). This is the same bias–variance trade-off as Monte Carlo versus temporal-difference learning in section 6.

Advantages for each turn of a real Wordle game

The critic here is deliberately crude: it only knows the turn number, and predicts the average remaining reward our logged Wordle games earned from that turn on. No discounting (\(\gamma = 1\)), as is common for language-model training.

Slide λ to 0 and each turn is judged by its own reward against the critic's expectation; slide it to 1 and every turn shares credit for the final win or loss.

Step 3: reusing a batch (importance sampling and trust regions)

Sampling is the expensive part (for a language model, generating text). REINFORCE takes one gradient step and throws the samples away, because after the step they no longer come from the current policy. Importance sampling fixes that by reweighting each sample by how much more or less likely the new policy makes it:

$$\rho_t(\theta) = \frac{\pi_\theta(a_t \mid s_t)}{\pi_{\text{old}}(a_t \mid s_t)}, \qquad L(\theta) = \mathbb{E}_{a_t \sim \pi_{\text{old}}}\big[\rho_t(\theta)\, \hat{A}_t\big]$$

At \(\theta = \theta_{\text{old}}\), \(\rho_t = 1\) and \(\nabla_\theta L\) equals the policy gradient exactly, so maximizing this surrogate objective over several steps is a natural way to squeeze more out of one batch. The catch: the advantages were measured under \(\pi_{\text{old}}\), so the surrogate is only trustworthy near it. Push too far and the policy chases noise in one small batch. Trust region policy optimization (TRPO; Schulman et al., 2015) adds a hard limit on how far the policy may move, measured by the Kullback–Leibler divergence (KL, a distance between probability distributions):

$$\max_\theta\ L(\theta) \quad \text{subject to} \quad \mathbb{E}_t\big[D_{\mathrm{KL}}\big(\pi_{\text{old}}(\cdot \mid s_t) \,\Vert\, \pi_\theta(\cdot \mid s_t)\big)\big] \le \delta$$

That works, but enforcing the constraint needs second-order optimization, which is awkward at scale.

Step 4: the clipped objective

Proximal policy optimization (Schulman et al., 2017) gets most of the same effect with plain gradient descent. It removes the incentive to move \(\rho_t\) outside \([1-\epsilon,\ 1+\epsilon]\):

$$L^{\text{clip}}(\theta) = \mathbb{E}_t\Big[\min\big(\rho_t \hat{A}_t,\ \operatorname{clip}(\rho_t,\,1-\epsilon,\,1+\epsilon)\,\hat{A}_t\big)\Big]$$
  • Good action (\(\hat{A}_t > 0\)): raising its probability pays off until \(\rho_t = 1+\epsilon\), then the objective goes flat and the gradient is zero.
  • Bad action (\(\hat{A}_t < 0\)): lowering its probability pays off until \(\rho_t = 1-\epsilon\), then flat.
  • The \(\min\) keeps the unclipped term whenever it is worse. If an update accidentally made a bad action more likely, the objective still sees the full penalty and pushes back. The objective is a pessimistic estimate.

Step 5: the whole algorithm

PPO trains actor and critic together (often sharing one network) on one combined loss, where the entropy bonus \(\mathcal{H}\) keeps some exploration:

$$L(\theta, \phi) = -L^{\text{clip}}(\theta) + c_1\, L^V(\phi) - c_2\, \mathcal{H}\big[\pi_\theta(\cdot \mid s_t)\big]$$
  1. Run the current policy \(\pi_{\text{old}}\) to collect a batch of steps.
  2. Compute advantages \(\hat{A}_t\) with GAE from the critic, and return targets \(\hat{G}_t = \hat{A}_t + V(s_t)\).
  3. For \(K\) epochs, take minibatch gradient steps on the loss above.
  4. Set \(\pi_{\text{old}} \leftarrow \pi_\theta\) and repeat.

Probability of the best action, averaged over 100 runs

With a few epochs, reuse learns faster from the same samples. Raise K and the unclipped version starts overfitting each noisy batch: some runs lock onto a worse action, and the average distance moved per batch (the KL divergence) jumps. Clipping removes the incentive to move far on any one batch, so the policy stays close to the data. A larger learning rate would also speed up plain REINFORCE, but it would not get more learning out of each expensive sample.

Many small details matter in practice: advantage normalization, clipping the value loss, learning-rate schedules, stopping early when the KL divergence grows too large. Huang et al. (2022) list 37 of them.

9Training language models with reinforcement learning

A language model is a policy over tokens. For tasks with checkable answers, sample several answers per question, score them, and push up the ones that beat their group's average. That is group-relative policy optimization (GRPO).

As a decision process: the state is the prompt plus the tokens written so far, \(s_t = (x, y_{<t})\); the action is the next token \(y_t\); the reward usually arrives once at the end, from a checker \(r(x, y)\). Rewards from a program rather than a human are called verifiable rewards; that is what Reasoning Gym and GEM provide.

Proximal policy optimization (PPO) for language models

This is the method behind reinforcement learning from human feedback (RLHF) in InstructGPT (Ouyang et al., 2022). Each token is one step of section 8's algorithm, and the ratio \(\rho_t\) compares token probabilities under the new and old model. Two parts are specific to language models:

  • The reward is a score for the finished answer, from a learned reward model (trained on human preferences) or a checker. Each token also pays a small penalty for drifting from the starting model, \(-\beta \log\big(\pi_\theta(y_t) / \pi_{\text{ref}}(y_t)\big)\).
  • The critic must predict, after every token, how the answer will be scored. It is usually a copy of the language model with a value head, so training holds two large models in memory.

Group-relative policy optimization (GRPO)

This method (Shao et al., 2024, used for DeepSeek-R1) drops the critic. For each prompt it samples a group of \(G\) answers, scores them, and uses each answer's standing within its group as the advantage for every one of its tokens:

$$A_i = \frac{r_i - \operatorname{mean}(r_1, \dots, r_G)}{\operatorname{std}(r_1, \dots, r_G)}$$ $$\begin{aligned} J(\theta) = {} & \frac{1}{G}\sum_{i=1}^{G} \frac{1}{|y_i|} \sum_{t=1}^{|y_i|} \min\big(\rho_{i,t} A_i,\ \operatorname{clip}(\rho_{i,t}, 1-\epsilon, 1+\epsilon) A_i\big) \ & -\, \beta\, D_{\mathrm{KL}}\big(\pi_\theta \,\Vert\, \pi_{\text{ref}}\big) \end{aligned}$$

The last term is a Kullback–Leibler divergence penalty that keeps the model near its starting point \(\pi_{\text{ref}}\), so it doesn't forget how to write while chasing reward.

Group-relative policy optimization on one puzzle, by hand

A toy model answers with one of four kinds of reply. Scoring uses GEM's game rules: correct +1, wrong 0, no parseable answer −0.1.

Train it and look at which correct answer wins. Both score +1, so group-relative policy optimization has no reason to prefer the concise one: whichever gets lucky early snowballs. If you want short answers, the reward has to say so. Notice too how many groups carry no signal once the model is usually right.

Two things the toy makes visible:

  • No spread, no signal. If every answer in the group gets the same score, every advantage is zero and nothing is learned. Haiku won all 6 of our episodes, so as a training batch for Haiku they would teach it nothing. Tasks must be hard enough to sometimes fail and easy enough to sometimes succeed, which is why Reasoning Gym lets you dial difficulty.
  • Length matters. Qwen with thinking on ran out of tokens before answering in 3 of its 6 games, scoring −0.1 each time; group-relative policy optimization (GRPO) would push those rambling replies down. The \(1/|y_i|\) term also has side effects: Liu et al. (2025) showed it penalizes long wrong answers less per token, which can make models wordier, and proposed dropping it (their "Dr. GRPO" variant).

10What is the state of a language-model agent?

A language-model agent has no hidden memory between turns: its state is whatever we hand it each turn. Choosing that hand-off is the "state transfer" question this project is named for.

In section 2 the ideal state for Guess the Number was a belief: two numbers, the low and high end of what's still possible. Our agents never get that. Each turn, render_prompt in run.py hands them a block of text, and they must re-derive the belief from it. Possible hand-offs:

  • Full history, thinking included. Nothing is lost, but the prompt grows every turn.
  • Full history without earlier thinking. What we do now, and what Qwen's own chat template does. Smaller, but the model re-plans from scratch each turn.
  • Rules plus the latest feedback only. Tiny, but it breaks the Markov property: earlier hints are gone.
  • A compact belief. Hand over a summary ("it's between 7 and 9"). Ideal if the summary is right, but someone has to write it: a program, the model itself, or a learned module.
  • Hidden state instead of text. Carry the model's internal state between turns (its attention key–value cache or hidden activations) rather than re-reading text. Recurrent and state-space architectures (for example Mamba) do this by design, compressing all history into a fixed-size vector.
